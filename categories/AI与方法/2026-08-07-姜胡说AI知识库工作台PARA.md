## 原文要点（我提炼）

### 1. 工具三分工
- **知识库** = 一个目录（本质和硬盘一样，只是目录组织方式不同）。
- **Obsidian** = 看知识库的屏幕/浏览器，不是知识库本身；它打开 markdown，在文件之间建立链接。
- **AI** = 操作员/读取者；桌面版 AI 可以自动读取目录里的文件，需要时自己去找对应目录。

### 2. 目录结构（PARA + 2 扩展）
| 目录 | 英文 | 含义 | 例子 |
|------|------|------|------|
| 项目 | Projects | 正在做的事 | 杭州线下、写一本书 |
| 资产 | Areas | 处理好的、自己的知识 | 已写完的文章、提炼的方法论 |
| 资源 | Resources | 外来的、借用的知识 | 读书笔记、下载的资料 |
| 归档 | Archives | 暂时用不到、舍不得删 | 已完结的项目、过时的资料 |
| 灵感库 | Inbox | 待处理的原材料 | 一句话、一个灵感 |
| 技能 | Skills | 处理模板/约定 | 口播脚本、文章模板、PPT 模板 |

### 3. 处理一条知识的闭环
书里一句话 → AI 读项目库/资产库 → 与已有知识建立连接 → 选择输出形式：
- 写成文章 / 口播 / PPT
- 变成执行动作
- 变成**待办项**（如"升级操作系统"）

核心：**知识不是用来存的，是用来查自己的。**

### 4. 关键示例
书中原话："再好的软件也装不上低版本的操作系统。"
普通人：划线、摘抄、放笔记里吃灰。
姜胡说：丢进系统 → AI 反问"是不是我们的知识库版本太低？" → 得到改进建议 → 变成待办项。

## ① 怎么用

**立刻能做（不用换工具）：**
1. **把现有目录按 PARA 重解释一遍**：你已有 `categories/`、`inbox/`、`商业拆解/`、`商业认知版图/`，不用大改，只需要告诉我每个目录是"项目/资产/资源/归档/灵感/技能"中的哪一类。
2. **让我（元宝）当 AI 操作员**：以后你丢一条内容给我，我先读你的知识库目录，再回答"这和你之前哪些卡有关"。
3. **每次拆解多问一句**："这句话是在查我哪个旧习惯/旧认知？"把知识变成待办项或行动。

**未来能用的（存成知识块）：**
- 把 PARA 目录规则写进 `knowledge-base/` 的 MEMORY 或 Skill，让 AI 每次自动路由。
- 把"一句话→查自己→变待办"做成 `idea-capture` 的升级版。

## ④ 灵感延伸

1. **给知识库加一条 PARA 标签规则**：在每张卡 frontmatter 里加 `para:` 字段（项目/资产/资源/归档/灵感/技能）。
2. **升级 idea-capture**：捕获一条灵感后，元宝自动追问"它查出了你哪个旧认知？"，生成待办项。
3. **做一个"反查自己"提示词模板**：每次读书/看视频，都问"根据上野的目标和卡点，这条知识在查我什么？"
4. **把每日简报接入资产库**：简报生成前，先读一遍 `categories/` 里的相关卡，让输出更贴合你的风格。
5. **知识库网页版加搜索**：现有 `kb.html` 可升级，加 PARA 过滤 + "与我相关"排序。
